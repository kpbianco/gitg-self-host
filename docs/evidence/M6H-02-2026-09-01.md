## Owner archive inventory

`grounded-growth-owner-private-archive-v1` contains the signed-in owner's
account identity, assessment runs and normalized results, baselines and lever
state, practice sprints/check-ins/evidence/score snapshots/reviews, optional
pilot feedback, assessment/practice context, Personal OS revisions, and weekly
plans/reviews. Relationships use deterministic archive references or public
stable curriculum identifiers rather than database keys.

The archive includes private narrative and declares `privacy_class=owner-private`
and `safe_for_sharing=false`. It excludes password hashes, session/auth state,
staff/group assignments, other users, database primary keys, opaque UUID record
identifiers, secrets, logs, server environment, and deployment metadata. The
existing evidence and pilot-feedback exports remain separately minimized.

## Deletion and retention controls

- `GG-OWNER-DELETION-1.0` previews exact grouped owner/session record counts.
- The signed preview is owner-bound and expires after 15 minutes.
- Execution requires the current password and exact phrase `DELETE MY ACCOUNT`.
- One transaction removes the explicit owner dependency graph, attributable
  sessions, and account. Injected-failure tests prove rollback.
- Canonical content, migrations, deployment state, and other users are preserved.
- `GG-OWNER-RETENTION-1.0` is disabled by default and has no timer or startup
  mutation. When deliberately enabled, only old draft check-ins and optional
  pilot feedback are eligible after preview and exact confirmation.
- Existing backups are separate private artifacts and are not silently rewritten.

## Backup, upgrade, and rollback proof

`backup_database` uses SQLite's online API and writes a `0600` snapshot plus
`grounded-growth-sqlite-backup-v1` sidecar. Existing snapshots and sidecars are
never overwritten. The sidecar contains only file/migration/table counts and
hashes. Critical fingerprints cover account, assessment run, orientation and
archetype results, baselines/current lever state, practice/check-in/evidence/
scores/reviews, feedback, context, Personal OS, and weekly records.

`verify_database_backup` rejects file, integrity, migration, or logical-state
drift. `--compare-live` requires exact migration and critical-state equality.
The Compose drill verifies this before recreation and again after stopped-state
restore, then reruns evidence, score, weekly, operations, and health gates.
