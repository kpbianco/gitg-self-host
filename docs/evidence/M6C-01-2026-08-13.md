## Independent system-risk review repair

The independent review found that context rows rejected `save`, `update`, and
`bulk_update` after creation but still allowed direct instance or queryset
deletion. Deleting the latest revision could erase append-only history while
leaving a contiguous series that readiness would accept. The repair adds model
and queryset deletion guards for both context models. The behavioral regression
test proves direct deletion fails and both rows remain present.

The review also corrected an overbroad privacy claim: canonical snapshots
deliberately retain assessment-epoch and protocol stable IDs for scope. They
exclude user identity, context-record UUIDs, timestamps, and narrative; they do
not exclude every database identifier.

idempotent.

migration depends on 0008, migrate `growth` back to `0007_pilotfeedback`; this
drops only M6C-01 context records. Then revert the batch. Do not reverse after
later dependencies without a separately reviewed rollback plan.

  interpretation. A later ranking formula needs a separate version, golden
  fixtures, explanation, and review.
- The agent completed a static non-judgmental-language audit. Required owner
  manual review of factor definitions before merge is unperformed.
- Accessibility, cultural meaning, safety/privacy usability, burden, and
  longitudinal usefulness of these definitions remain unvalidated.

  backups. Context-specific UI, consent, export, deletion, retention, and
  purge behavior is outside M6C-01 and remains deferred.
- Concurrent context writers were not exercised. The service locks the
  assessment epoch, but SQLite does not implement row-level `SELECT FOR
  UPDATE`; a later UI write path needs an explicit SQLite concurrency test and
  reviewed retry/conflict behavior before relying on concurrent idempotency.
- The active batch allows a standalone context readiness command but forbids
  editing the existing verification runner, GitHub workflow, and Compose
  script. Therefore `make context-check` was run separately; CI and Compose do
  not yet invoke the new management command directly. New context tests are
  included in the existing CI pytest job.
- Some older control/target prose still reflects the superseded sequencing in
  which M6B governance blocked all later work. The canonical M6C-01 contract
