## Independent system-risk review repairs

The post-implementation review found and repaired two material failure modes:

1. The service previously read need state, assessment context, and each practice
   context in separate autocommit queries. A concurrent context append or
   score-state transition could therefore produce a mixed-time result. The
   service now re-fetches and locks the assessment epoch inside one transaction
   before reading every mutable input; SQLite uses one transaction snapshot.
2. Baselines and current state were filtered by the supplied user before their
   ownership was validated. If an entire current-state cohort was corruptly
   cross-owned, it disappeared from the query and the service could silently
   fall back to baseline needs. The service now loads epoch rows first and
   fails closed on any ownership mismatch.

The missing deferred-source alternative behavior test was also added. It
proves that a deferred candidate returns the highest-ranked distinct eligible
candidate with the `alternative_after_deferred` explanation. Additional tests
prove the epoch lock/transaction boundary and the cross-owned-state failure.
